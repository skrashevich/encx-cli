# encx-mock

`encx-mock` — локальный HTTP-сервер с состоянием, который реализует используемые
`encli` endpoints Encounter. Он предназначен для разработки клиента,
интеграционных тестов и проверки retry/timeout-логики без запросов к реальному
домену Encounter.

Это не полная реализация Encounter. Сервер не следует открывать в недоверенную
сеть: настоящей аутентификации нет, почти любые credentials принимаются.

## Быстрый старт

Запуск из репозитория:

```sh
go run ./cmd/encx-mock
```

Или установка и запуск бинарника:

```sh
go install github.com/skrashevich/encx-cli/cmd/encx-mock@latest
encx-mock
```

По умолчанию сервер слушает `0.0.0.0:18080`. В другом терминале:

```sh
encli login -domain 127.0.0.1:18080 -http -login demo -password demo
encli game-list -domain 127.0.0.1:18080 -http
encli status -domain 127.0.0.1:18080 -http -game-id 424242
encli send-code -domain 127.0.0.1:18080 -http -game-id 424242 1
```

Можно использовать любой логин и пароль, кроме `fail:fail`: эта пара специально
возвращает ошибку аутентификации. Прогресс хранится в памяти и разделяется между
всеми сессиями с одинаковой парой логин/пароль. Чтобы начать игру сначала,
перезапустите сервер или используйте другую пару.

## Встроенная игра

Без дополнительных параметров сервер создаёт игру `424242`, команду `5150` и
три уровня по четыре сектора.

| Уровень | Коды секторов | Код закрытия всего уровня |
| --- | --- | --- |
| 1 | `1`, `2`, `3`, `4` | `CODE-1` |
| 2 | `5`, `6`, `7`, `8` | `CODE-2` |
| 3 | `9`, `10`, `11`, `12` | `CODE-3` |

Код сектора закрывает один сектор, а `CODE-N` — весь текущий уровень.
Неправильные ответы сохраняются в истории действий. Во встроенном fixture также
есть тестовые бонусы; текст задания бонуса принимается как ответ на него.

## Настройка

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `ENCX_MOCK_ADDR` | `0.0.0.0:18080` | Адрес HTTP-сервера |
| `-scenario PATH` | нет | Загрузить экспорт Encounter `Game scenario.html` |
| `ENCX_MOCK_SCENARIO` | нет | Путь к сценарию, если не задан `-scenario` |
| `ENCX_MOCK_HAR` | встроенные fixtures | Загрузить очищенный профиль форм и вариантов протокола из HAR |
| `ENCX_MOCK_ANTIBOT_ATTEMPTS` | нет | Номера попыток ответа через запятую, для которых вернуть mock anti-bot redirect |
| `-v`, `--version`, `version` | | Вывести версию бинарника |

Флаг `-scenario` имеет приоритет над `ENCX_MOCK_SCENARIO`.

## Запуск с экспортом сценария

Режим сценария читает HTML-экспорт страницы Encounter `Game scenario`:

```sh
encx-mock -scenario "/path/to/Game scenario.html"

# Эквивалентный вариант:
ENCX_MOCK_SCENARIO="/path/to/Game scenario.html" encx-mock
```

Из экспорта используются название игры, уровни, задания, ответы секторов,
бонусы, подсказки и таймеры автоперехода. Ответы сравниваются без учёта регистра
и незначащих различий в пробелах. Встроенные сокращения `CODE-N` в этом режиме
отключены: принимаются только ответы из экспорта.

Локальные файлы, на которые ссылается экспорт, по возможности встраиваются как
`data:` URL. Отсутствующие файлы перечисляются при запуске.

## Сценарий для App Store Review

В репозитории есть безопасный fixture для проверки iOS-приложения ревьюерами
Apple без доступа к реальному Encounter:

```sh
go run ./cmd/encx-mock -scenario cmd/encx-mock/fixtures/app_store_review_scenario.html
```

Для проверки с физического iPhone сервер должен быть доступен в локальной сети:

```sh
ENCX_MOCK_ADDR=0.0.0.0:18080 \
  encx-mock -scenario /path/to/app_store_review_scenario.html
```

В настройках приложения укажите HTTP endpoint mock-сервера, например
`http://<LAN-IP>:18080`. Можно использовать любой логин и пароль, например
`apple-review` / `apple-review`.

Игровые данные fixture:

| Уровень | Название | Коды |
| --- | --- | --- |
| 1 | `Welcome` | `REVIEW-START` |
| 2 | `Checkpoint` | `MAP-101`, `LOCK-202`; бонус `BONUS-5` |
| 3 | `Finish` | `FINISH-303`; автопереход через 30 секунд |

Дополнительно можно отправить неправильный ответ, чтобы проверить отображение
ошибки, и код `PZDC`, чтобы включить эмуляцию потери сети для текущей пары
логин/пароль.

## Профиль протокола из HAR

`ENCX_MOCK_HAR` потоково читает весь HAR при запуске и строит очищенный профиль
форм и вариантов протокольных ответов. Это добавочный режим: без переменной
остаются встроенная игра и её прежнее поведение, а режим сценария продолжает
работать независимо.

```sh
ENCX_MOCK_HAR=/path/to/dump.har encx-mock
```

Профиль извлекает наблюдаемые варианты игровых GET/POST-ответов, списка игр,
переходов и anti-bot redirects, а также топологию уровней. Он не копирует
захваченные значения: идентификаторы, cookies, ответы, задания, подсказки,
сообщения и другой игровой текст заменяются безопасными mock-значениями.
Исходный HAR читается только при запуске.

Не коммитьте raw HAR и любые captures с настоящими cookies, токенами,
ответами, идентичностями или содержимым игры. Для тестов подходят только
полностью синтетические и очищенные fixtures.

HAR можно сочетать со сценарием:

```sh
ENCX_MOCK_HAR=/path/to/protocol.har \
  encx-mock -scenario "/path/to/Game scenario.html"
```

В таком запуске сценарий полностью задаёт игровой контент, топологию уровней и
сопоставление ответов. HAR предоставляет только очищенные формы и варианты
протокола. User details всегда возвращаются из небольшого очищенного
встроенного шаблона.

В HAR были замечены одноразовые снимки перехода: `Level` равен `null`, `Levels`
пуст, а `Event` — непрозрачное числовое значение. Mock воспроизводит такой
вариант, когда он есть в профиле, и следующий GET возвращает активный уровень.
Значение `Event` и GET-параметр `level` не получают в документации
предполагаемого смысла.

## Эмуляция anti-bot redirect

`ENCX_MOCK_ANTIBOT_ATTEMPTS` задаёт через запятую положительные номера попыток
ответа в одной mock-сессии, на которых сервер вернёт `302` на безопасный
локальный `NotHumanRequest.aspx`:

```sh
ENCX_MOCK_ANTIBOT_ATTEMPTS=1,3 encx-mock
```

Это отдельная проверка от `PZDC`. `PZDC` включает эмуляцию потери сети и не
расходует попытку anti-bot redirect.

## Эмуляция потери сети

Отправьте `PZDC` как ответ уровня, чтобы на минуту включить задержку запросов для
текущей пары логин/пароль:

```sh
encli send-code -domain 127.0.0.1:18080 -http -game-id 424242 PZDC
```

В течение этой минуты каждый запрос ждёт до двух секунд без данных. Клиент с
меньшим timeout получает timeout; клиент с большим timeout после двух секунд
может получить пустой ответ. Для немедленного продолжения используйте другую
пару логин/пароль или перезапустите сервер.

## Docker

В контейнере сервер должен слушать все интерфейсы. Файлы сценария и HAR нужно
смонтировать внутрь контейнера:

```sh
docker run --rm -p 18080:18080 \
  -e ENCX_MOCK_ADDR=0.0.0.0:18080 \
  ghcr.io/skrashevich/encx-mock

docker run --rm -p 18080:18080 \
  -e ENCX_MOCK_ADDR=0.0.0.0:18080 \
  -v "$PWD/fixtures:/fixtures:ro" \
  ghcr.io/skrashevich/encx-mock \
  -scenario /fixtures/Game-scenario.html
```

## Админские маршруты нового движка

Флаг `-engine new` или `-engine both` включает, помимо игровых маршрутов,
редактируемую половину игры: уровни и их задания, подсказки (обычные и
штрафные), бонусы, секторы с ответами, сообщения, настройки уровня и параметры
игры. Это то же состояние, что видят игровые маршруты, поэтому обе половины
мока описывают одну игру.

```sh
encx-mock -engine both
encli -domain 127.0.0.1:18080 -http -api-base-url http://127.0.0.1:18080 \
  -engine new -game-id 424242 admin-level-content 1
```

Формы ответов сняты с живого demo.en.cx, а не выписаны из
`docs/newengine/swagger.json`: спецификация уже дважды оказывалась неверна
насчёт этого API, и мок, написанный по ней, повторил бы ровно те допущения,
которые живой аудит опроверг. Эталонные документы лежат в
`fixtures/live_*.json`, а тесты `admin_shape_test.go` держат ответы мока против
них — в том числе проверяют, что мок не выдумывает полей, которых движок не
шлёт, и что награда автопрохода остаётся знаковой (штраф отрицателен).

### Воспроизведение дефектов развёрнутого бэкенда

`-quirks` (или `ENCX_MOCK_QUIRKS`) включает поведение, которое у настоящего
сервера есть, а у корректного движка быть не должно. По умолчанию мок —
эталонная реализация протокола.

| Квирк | Что воспроизводит |
| --- | --- |
| `reorder-noop` | `POST .../levels/exchange` и `.../put` отвечают `204` и не меняют порядок уровней — так ведёт себя api.en.cx сегодня |

```sh
encx-mock -engine both -quirks reorder-noop
```

Это нужно, чтобы офлайн проверялись обе ветки клиента: при обычном моке
перестановка уровней проходит, а при квирке `encx` обязан заметить, что движок
ответил успехом и ничего не сделал.

## Реализованное поведение и ограничения

Сервер покрывает логин, user details, список и детали игр, принятие команды,
игровые GET/POST-запросы, статистику, подтверждение взноса и заглушку anti-spam,
а на новом движке — ещё и админскую половину (см. выше).

Состояние хранится только в памяти. Доступна одна фиксированная игра и команда;
нет постоянного хранилища, TLS и полной эмуляции правил Encounter. Неизвестные
ID игр и маршруты возвращают `404`. Ответ на обращение без сессии зависит от
маршрута — см. таблицу ниже.

Прогресс игры мок хранит по сессиям, поэтому анонимный читатель публичной
статистики видит игру с начала, а не позицию другого игрока. Это ограничение
модели состояния мока, а не движка.

### Анонимный доступ

Что отдают маршруты без сессии — измерено на боевых стендах 01.09.2026
(`svk.en.cx` для legacy, `api.en.cx` с `X-En-Domain: demo.en.cx` для нового)
и воспроизведено моком один в один:

| маршрут | ответ без сессии |
|---|---|
| `GET /gameengines/encounter/play/{id}` (legacy) | `302` → `/login.aspx?return=…` |
| `GET /MakeGameFee.aspx` | `302` → `/Login.aspx?return=…` |
| `GET /UserDetails.aspx`, `GET /Teams/TeamDetails.aspx` | `403` + страница «Требуется вход» |
| `GET /home/?json=1` | `200`, полный каталог |
| `GET /gamestatistics/full/{id}?json=1` | `200`, полный документ |
| `GET /GameDetails.aspx?gid=…` | `200` |
| `GET /gameengines/{c}/play/{id}` (новый) | `401 {"error":"unauthorized","message":"unauthorized","code":401}` |
| `/admin/**`, `GET /games/{id}/monitoring` | `401` с `"message":"Authorization required"` |
| `GET /games/{id}/corrections` | публичный |

Оба движка проверяют сессию раньше всего остального: ответ одинаков с `json=1`
и без него, и для несуществующего `gameId`. Различие между `401` и редиректом
принципиально, а не косметично — `encx` разбирает тело ответа legacy-движка не
глядя на статус, поэтому JSON-ответ `401` парсился бы в пустую `GameModel` и
вызов отчитывался бы успехом. Редирект заставляет клиента поставить тот же
диагноз, что и на бою: `session expired or access denied`.

Регистр пути входа движок пишет по-разному (`/login.aspx` с игрового движка,
`/Login.aspx` со страницы взноса); IIS регистр не различает, а `http.ServeMux`
различает, поэтому мок обслуживает оба написания.

Сессию на новом движке мок принимает и кукой `SESSION_ID`, и заголовком
`Authorization: Bearer <token>` — мобильная сессия (`no_cookie`) кук не несёт.

Маршруты нечувствительны к завершающему слэшу: `POST /login/signin` и
`POST /login/signin/` обрабатываются одинаково, как это делает боевой ASP.NET
за IIS. Само по себе `http.ServeMux` так не умеет — форма со слэшем провалилась
бы в catch-all `GET /` и вернула `405`, — поэтому регистрация идёт через
`tolerantMux` (`routing.go`), который заводит обе формы.

**Админка старого движка не эмулируется.** Её страницы — HTML, который парсится
регулярными выражениями, и написать этот HTML можно было бы только по самим
парсерам: такой мок доказывал бы, что парсеры согласны сами с собой. Реального
захвата ASP-админки в репозитории нет, поэтому `-engine legacy` покрывает только
игровую половину.
