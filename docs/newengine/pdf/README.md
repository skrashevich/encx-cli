# Сборка PDF по документации нового движка

```sh
./docs/newengine/pdf/build.sh                 # -> docs/newengine/encounter-new-engine.pdf
./docs/newengine/pdf/build.sh /tmp/движок.pdf # другой путь
```

Скрипт собирает `README.md`, `engine-websocket.md` и `parity.md` из
`docs/newengine/` в один документ: обложка, оглавление, три главы,
колонтитулы и нумерация страниц. Правки в исходных `.md` подхватываются
автоматически — заголовки второго уровня попадают в оглавление сами.

Дата снимка и версия спецификации на обложке читаются из `README.md`
(строки «Снимок сделан:» и «Версия документа:»), чтобы не разойтись с ним.

## Требования

| | |
|---|---|
| `pandoc` | markdown → HTML (`brew install pandoc`) |
| `node` ≥ 22 | печать через CDP; в более старых нет встроенного `WebSocket` |
| Google Chrome | или Chromium; нестандартный путь — через `CHROME_BIN` |
| сеть (однократно) | `paged.js` кладётся в `.cache/` и дальше берётся оттуда |

## Из чего состоит

| Файл | Роль |
|---|---|
| `build.sh` | весь конвейер: подготовка markdown, pandoc, печать |
| `template.html` | обложка, страница содержания, каркас документа |
| `style.css` | вёрстка: PT Serif/PT Sans/PT Mono, таблицы, код, колонтитулы, `@page` |
| `print.js` | печать HTML в PDF через Chrome DevTools Protocol |

`chrome --headless --print-to-pdf` здесь не годится: он снимает PDF по событию
`load`, когда paged.js ещё раскладывает документ, и отдаёт первые две-три
страницы. `print.js` дожидается конца раскладки и только потом печатает.

## Известное ограничение

При переносе длинной таблицы на следующую страницу paged.js не повторяет её
шапку. У всех таблиц паритета шапка одинаковая («Метод `encx.Client` — Старый
движок — Новый движок»), поэтому на читаемость это не влияет.
