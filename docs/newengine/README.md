# Новый движок Encounter (Go Backend API)

Encounter переезжает с ASP.NET на новый бэкенд («Encounter Go Backend API»).
`encx` поддерживает оба движка одновременно: публичный API `encx.Client`
не зависит от того, какой движок обслуживает домен.

## Спецификация

- Источник: <https://api.en.cx/swagger/doc.json> (Swagger UI: <https://api.en.cx/swagger/index.html>)
- Копия в репозитории: [`swagger.json`](swagger.json)
- Снимок сделан: 2026-08-31
- Версия документа: Swagger 2.0, 478 путей, 450 определений

Обновление снимка:

```sh
curl -s https://api.en.cx/swagger/doc.json -o docs/newengine/swagger.json
go test ./encx/enapi/ -run TestSpec
```

Тест `TestSpec...` в `encx/enapi` следит за тем, что копия остаётся валидным
Swagger-документом и содержит маршруты, на которые опирается клиент.

## Ключевые отличия от старого движка

| | Старый движок (ASP.NET) | Новый движок (Go Backend) |
|---|---|---|
| Базовый URL | `https://{domain}` | `https://api.en.cx` (домен передаётся заголовком) |
| Контекст сайта | сам хост | заголовок `X-En-Domain: {domain}` |
| Авторизация | session-cookie после `/login/signin` | JWT: `Authorization: Bearer <token>` + cookie `en_access` |
| Формат полей | `PascalCase` | `snake_case` |
| Админка | HTML-формы `/Administration/**` | REST `/admin/games/**` |
| Ошибки | HTML-страница либо `Error` в JSON | `{"error":…,"message":…,"code":…}` или `{"sentence_key":…}` |

Новый бэкенд сохраняет ASP-совместимые маршруты игрового движка
(`/gameengines/{controller}/play/{gameId}`), но отвечает моделью
`models.EngineState` в snake_case, поэтому `encx` выполняет маппинг в
привычный `encx.GameModel`.

## Как выбрать движок

По умолчанию — `auto`: клиент один раз спрашивает
`GET /sites/domain/{domain}` и запоминает ответ.

| Ответ | Вывод |
|---|---|
| `200` с описанием сайта | домен переехал, работаем по новому движку |
| `404 domain_unregistered` | домен ещё на ASP.NET |

Проверять доступность хоста (`GET /version`) для этого нельзя: один API-хост
обслуживает всю зону и отвечает `200` на запрос с любым `X-En-Domain`, включая
несуществующий, — такая проба объявила бы переехавшими все сайты сразу.

Две проверки ограничивают, кому клиент вообще готов представиться:

1. **Хост выводится только для зон Encounter** — `en.cx`, `encounter.cx`,
   `encounter.ru`, `en-world.org`, `quest.ua`. Иначе отрезание одной метки
   превратило бы `quest.example.com` в `api.example.com`, то есть отправило бы
   заголовок сайта, а при входе — логин и пароль на чужой хост. Для домена вне
   этих зон хост не выводится вообще: в режиме `auto` клиент остаётся на старом
   движке, а при явном `-engine new` запрос не отправляется и возвращается
   ошибка с указанием задать `-api-base-url`. Подставлять `api.en.cx` в этом
   случае нельзя — это легитимный хост Encounter, но он не обслуживает чужой
   домен, и пароль ушёл бы не туда.
2. **Сайт должен подтвердить домен** — ответ проверяется по `primary_domain` и
   списку `domains`. Сайт, который не называет наш домен, отклоняется. Сайт, не
   назвавший вообще ни одного домена, принимается только если API-хост задал
   сам вызывающий: этим он за хост поручился.

Кэшируется только определённый ответ. `404` — это «домен ещё на ASP.NET», он не
изменится; сетевой сбой или отменённый контекст вердиктом не считаются, чтобы
долгоживущий клиент не остался прибит к старому движку из-за одного обрыва.

```go
c := encx.New("demo.en.cx")                                   // auto
c := encx.New("demo.en.cx", encx.WithEngine(encx.EngineNew))  // принудительно
```

Либо через окружение — `ENCX_ENGINE=legacy|new|auto` — либо флагом CLI
`encli -engine new`. Хост нового движка переопределяется через
`encx.WithAPIBaseURL(...)`, `-api-base-url` или `ENCX_API_BASE_URL`.

Матрица паритета методов приведена в [`parity.md`](parity.md).
